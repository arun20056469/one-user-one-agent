# One User, One Agent

An agent that owns **one OTT viewer's goal at a time**: it reads what is known
about the viewer, commits to a single measurable goal, decides what (if
anything) to change, acts inside the latency budget, verifies its own decision
independently, closes the loop by judging the goal later, and proves impact by
comparing the **randomized agent arm against the holdout arm**.

The core is deterministic and rule-based; a language model is only ever an
*advisor*. The default model provider is a replay/mock provider, so **the whole
thing runs with one command and no API key**.

> **Honest result up front.** On the delivered replay day the agent's
> intention-to-treat difference is **−0.38 pp (95% CI [−4.08, +3.32])** — the
> interval crosses zero, so the report says *"no detectable effect yet"*. That
> is the correct answer for one day of data; an inflated number would score
> worse. See `sample_run/final_report.md` and `sample_run/impact_report.md`.

---

## 1. Run it (one command, no API key)

```bash
python -m src.main run --pack data_pack --out sample_run
```

That runs the full loop — **replay → simulate → judge → impact** — and writes
the entire `sample_run/` bundle. It is idempotent: running it again into the
same directory reproduces the same run (replay resets its own state first).

Requirements: **Python 3.10+** (developed and tested on 3.14.6, Windows and
Linux). **No third-party packages** — standard library only, no
`requirements.txt` to install. No network access is needed.

Run the test suite (25 tests):

```bash
python -m unittest discover -s tests
```

The suite builds its own miniature data pack (a private copy) on first run via
`tools/generate_datapack.py`; nothing else to set up.

### Optional: rebuild the data pack

The pack ships in `data_pack/`. It is generated by one seed and is
byte-reproducible:

```bash
python tools/generate_datapack.py --out data_pack          # full pack (5,000 viewers)
python tools/generate_datapack.py --out mypack --viewers 200 --days 12 --triggers 60
```

### Run a single stage (for evaluators rerunning one part)

```bash
python -m src.main replay   --pack data_pack --out sample_run
python -m src.main simulate --pack data_pack --out sample_run --seed 7
python -m src.main judge    --pack data_pack --out sample_run
python -m src.main impact   --pack data_pack --out sample_run
python -m src.main audit    --pack data_pack --out sample_run   # safety table as JSON
```

All commands are listed in `RUN_COMMANDS.txt`.

### Swap in a real model (optional)

Implement `ModelProvider.propose()` in `src/provider.py` and pass
`--provider real`. Nothing else changes: model output is never evidence and
never approval — it still goes through the verifier. Budgets
(`max_model_calls=8`, `max_tool_calls=20`) are enforced by the agent, not the
provider.

## 2. What you get in `sample_run/`

| file | what it is |
|---|---|
| `decisions.jsonl` | one line per trigger: facts, goal, dialects + conflicts, action, copy, evidence, checks, confidence reason, assumptions, latency |
| `actions.jsonl` | what was actually **published or scheduled** (idempotency key, deeplink, schedule time) |
| `control_log.jsonl` | how each injected surprise (withdrawal, rule fix, surge, slow store) was handled live |
| `viewer_state/viewers.jsonl` | the durable per-viewer state at the end (facts, active goal, learnings, caps) |
| `viewer_state/state.db` | the SQLite store behind that export (audit any moment) |
| `outcomes.jsonl` | the judged result of every goal window |
| `outcome_events.jsonl`, `simulator_report.json` | the simulator's output the judge reads |
| `latency_report.json` | measured `decided_in_ms` distribution, budget breaches, fallbacks used |
| `impact_report.md`, `impact_summary.json` | agent-vs-holdout ITT, naive contrast, per-goal, pilot re-analysis |
| `final_report.md` | the whole run on one page, **generated from the run's own artefacts** |

`final_report.md` is written by the pipeline itself (see `src/report.py`), never
by hand, so its numbers cannot drift from `decisions.jsonl`/`outcomes.jsonl`.

## 3. What the agent does on each trigger (the 7-step loop)

1. **Understand the viewer** — resolve facts (subscription, consent, dialect,
   signup, engagement) with explicit precedence and freshness; keep every
   conflict visible. (`src/facts.py`)
2. **Choose one goal** — evaluate every goal in `config/goals.json`, pick the
   highest-priority eligible **and measurable** one, set the deadline; otherwise
   abstain with a reason. (`src/goals.py`)
3. **Decide the intervention** — home page / push / WhatsApp / in-app / nothing,
   using only real, available, in-dialect content. (`src/interventions.py`)
4. **Act within budget** — publish within 60 s (hard fail 5 min); ≤8 model and
   ≤20 tool calls per decision; failures fall back to rules or no action, never
   a blind guess. (`src/agent.py`)
5. **Verify before acting** — an independent verifier re-derives eligibility,
   dialect, availability, consent, quiet hours, frequency cap, policy, home-page
   shape, evidence resolvability, and rejects unsupported model claims. It can
   block or downgrade. (`src/verifier.py`)
6. **Close the loop** — after each deadline, judge SUCCEEDED / FAILED /
   INCONCLUSIVE from attributable events only; apply mid-day rule corrections to
   the affected open goals only; write learnings back to state. (`src/judge.py`)
7. **Prove impact** — ITT over randomized arms, with the naive
   served-vs-everyone-else comparison shown beside it and the pilot report
   re-analysed honestly. (`src/impact.py`)

## 4. Surprises handled (see `sample_run/final_report.md` §2 for the live table)

- duplicate events (same `event_id`) and duplicate trigger deliveries
- offline-buffered app opens days old (stale → no live action) and 5–30 min old
  (ageing → in-session surfaces only, never a push)
- day-stale / duplicated profile rows (freshest `row_updated_at` wins)
- dialect conflicts across app setting, campaign deeplink and profile (app
  setting wins; conflicts recorded)
- instructions hidden inside catalogue descriptions (content, never command)
- a withdrawn title mid-day (excluded by planner **and** verifier; pending
  actions cancelled)
- an unmeasurable goal (refused) and two underspecified goals (interpreted,
  interpretation recorded as an assumption)
- a mid-replay goal-rule correction (only affected open goals re-judged)
- injected model faults: timeout (retry once, then rule fallback), malformed
  JSON (parse safely, then fallback), and a confident but unsupported
  eligibility claim (rejected by the verifier)
- a 3× traffic surge (optional model calls skipped) and a slow data store
  (in-memory snapshot fallback), both while still meeting the latency budget

## 5. Tests and what they guarantee

25 tests (`python -m unittest discover -s tests`), mapped to the assignment's
required list:

| required test | where |
|---|---|
| late / duplicate trigger (no duplicate action, stale handled) | `test_triggers.py::test_duplicate_trigger_creates_one_action`, `::test_stale_offline_trigger_is_not_a_live_session`, `::test_ageing_trigger_never_sends_a_message` |
| conflicting source resolved correctly | `test_conflicts.py` (dialect → app setting; newer purchase beats stale profile; duplicate profile rows; brand-new user from events) |
| tool failure → safe fallback | `test_failures.py` (provider timeout, broken JSON, state-store failure, surge skips model call, budgets bounded) |
| corrected goal rule → only affected open goals | `test_rule_correction.py` |

Extra guarantees: quiet hours (schedule, never send), frequency cap, holdout gets
zero actions, injected catalogue instructions ignored, unsupported model claim
rejected, a row with fewer than three titles dropped, a withdrawn title never
used, and a full end-to-end run asserting the replay safety invariants plus the
honest impact artefacts. `test_end_to_end.py::test_rerun_into_same_dir_is_reproducible`
is the regression test for the one-command replay being re-runnable.
